## Known limitations
- **No remote, nothing pushed** — the repository has a local history (S01–S02, S03, S04–S05) but no remote is configured; pushing and pull requests still require an explicit instruction.
- **SDK 57 schema changes** — `newArchEnabled` removed, splash moved to `expo-splash-screen` plugin (R-24). Documentation updated.
- **Toolchain pinned below target baseline** — `react-native` `0.86.3` (from `0.86.2`), `jest` `~29.7.0` (from `^30.5.2`), `@types/jest` `29.5.14`. Added `babel-preset-expo`, `@typescript-eslint/*`, `expo-constants`, `react-native-web`, `@expo/metro-runtime`. Overrides: `react-dom: 19.2.3`, `expo-font: ~57.0.4`. See `context/architecture.md` §1.4, `context/risk-register.md` R-23.
- **`DateField` and `Attachment` are deferred** — they need `@react-native-community/datetimepicker` and `expo-image-picker` respectively; the latter is planned for S19 (R-16). The rest of ui-context §5 is implemented (R-25).
- **`Skeleton` has no shimmer** — it is static by design so it never disturbs tests or reduced-motion users.
- **Later client/admin destinations remain incomplete** — the submitted parent request now opens the dashboard, but downstream proposal, contract, invoice, payment and tutor workflows remain subject to their roadmap steps.
- **Draft auto-resume is not wired yet** — until S13/S14 supply persistence and the draft store, Get started opens request-type selection even if a draft cannot yet be restored.
- **Request draft is in-memory only** — S06–S10 store journey selection, client contact, child drafts, child-keyed needs and adult self needs; persistence is deferred until S14.
- **Child learning context does not create billable needs** — the onboarding subjects, goals and
  schedule are submitted as request context; parent submissions use no `LearningNeed` records.
  Proposal preparation for these context-only requests is deferred under R-41. The parent's
  address is captured with their contact details.
- **Submitted records are in-memory only** — requests, promoted children and needs, activity events and notifications created by S12 do not survive an app restart until S14.
- **Client profiles remain in memory until S14** — S10 can detect profiles already present in the client store, but durable profile lookup is not available until persistence is implemented. PIN creation and verification are local to the request flow.
- **Login is intentionally unavailable** — restored account lookup depends on later client and persistence steps; PIN creation and verification are not real authentication.
- **The Welcome language pill and Support link are presentational** — they render the active locale and a Support affordance but have no picker or destination yet; the admin entry is not on Welcome and remains available by direct route for the simulation.
- **A NativeWind development crash was worked around, not fixed upstream** — a `className` that adds a shadow utility at runtime crashes the app in development; the `SegmentedControl` and the `Card` always resolve a shadow class instead, and the rule is in `context/ui-context.md` §5.1 (R-30). Production builds are unaffected, but the same trap applies to any future component that toggles a shadow at runtime.
- **The admin tree is a URL segment, not an `(admin)` group** — required to produce the `/admin/...` URLs of architecture §3.2 without shadowing the client routes (R-26, Q13 — awaiting confirmation).
- **A stale URL parameter after a replace** — the param of the route being left is kept by React Navigation, so the not-found action on `/proposal/not-an-id` lands on `/dashboard?proposalId=not-an-id`. Cosmetic (R-27).
- **The header titles are derived** — the `nav.*` keys come from the screen names of `design.md`; `design.md` §2.1 now records them (R-28).
- **Admin French-only (prototype)** — R-15.
- **No authentication/authorisation** — R-17; admin simulation is unauthenticated by design.
- **Currency USD only** — R-19, pending confirmation.
- **Local-only, no backend** — R-18 deferred.
